LFI
Описание действий:
Открываем сайт http://51.250.73.193:8084, заходим на страничку Поиска. Включаем перехват утилитой BurpSuteCom, по указанию в поле поиска вводим text.txt, нажимаем Поиск. Перехватываем утилитой BurpSuteCom запрос GET

![Lighthouse Report](/images/Практ_раб_7_1_1.png)

Отправляем его в Intruder, настраиваем атаку Sniper, предварительно скачиваем с GitHab словарь directory_traversal.txt и загружаем его в настройках полезной нагрузки. Нажимаем Start Atack, после некоторого времени, в  результатах отфильтровываем по размеру и в окне Response делаем поиск flag. При рассмотрении файлов с размером 9563, был выявлен флаг flag{L0c@l_F1l3_Inclu0n}

![Lighthouse Report](/images/Практ_раб_7_1_2.png)

1.	Выявлена уязвимость LFI в РНР (серверной части)
2.	Для проведения захвата ссылки на виртуальную машину была использована утилита Burp Suite Com, со встроенным функционалом данной интегрированной платформы. 
3.	Для защиты от атаки LFI в РНР используются методы:
- Ограничение доступа к файлам
- Валидация и очистка пользовательского ввода
- Использование абсолютных путей и т.д.



Security Misconfiguration
Описание действий:
Запускаем скрипт pidrila 
python3 pidrila.py -u http://51.250.73.193:8083 -l /home/kali/
с указанием задающего целевого URL для сканирования и путь для сохранения логов сканирования.

![Lighthouse Report](/images/Практ_раб_7_2_1.png)

После проведенного сканирования смотрим в файле сохраненные данные и фильтруем

![Lighthouse Report](/images/Практ_раб_7_2_2.png)

открываем в браузере файл
http://51.250.73.193:8083/robots.txt, видим app.py путь к файлу относительно корня сайта

![Lighthouse Report](/images/Практ_раб_7_2_3.png)

Добавляем в данный URL app.py (http://51.250.73.193:8083/app.py) и находим наш flag{B3_C@r3fu11y_with_st@tic_p@th}

![Lighthouse Report](/images/Практ_раб_7_2_4.png)

1.	Выявлена уязвимость Security Misconfiguration (серверной части)
2.	Для проведения захвата ссылки на виртуальную машину была использована утилита pidrila.
3.	Для защиты от атаки Security Misconfiguration:
-	проводить ревизию конфигов приложения (не оставлять учётные данные в конфигах, если такое возможно, внимательно отнестись к тому, что закомментировано или что включено по умолчанию),
-	настроить редиректы со стандартных страниц (например, приветственная страница apache),
-	отключить вход пользователей по умолчанию (например, admin:admin),
-	ограничить права пользователя и службы, от чьего имени работает приложение и его компоненты (плохо: веб-сервер и база данных работает от имени администратора; хорошо: у каждого компонента свой пользователь с максимально ограниченными правами, которых достаточно для полноценного функционирования приложения),
-	постоянно обновлять компоненты приложения.
